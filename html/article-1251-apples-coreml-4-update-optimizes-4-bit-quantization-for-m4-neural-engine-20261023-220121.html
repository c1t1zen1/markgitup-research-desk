Apple’s CoreML 4 Update Optimizes 4-Bit Quantization for M4 Neural Engine

Recent updates to Apple's Core ML tools highlight increased Neural Engine throughput for int8-int8 compute on M4 chips, enhancing on-device LLM inference efficiency.

October 23, 2026 · 10:01 PM PDT · 6 min read · 12 sources · Original family: Quantized LLMs Running on Mac Hardware

Editor’s brief

Why this matters now

The evolution of on-device AI on Apple Silicon is driven by tight integration between hardware and software frameworks. Recent documentation from Apple's Core ML Tools indicates specific performance optimizations for the M4 chip, particularly regarding integer compute throughput on the Neural Engine. This technical shift aims to reduce latency and memory usage for quantized models running locally on Mac hardware.

Evidence for this analysis was gathered from official Apple developer documentation, independent benchmark repositories, and technical deep-dives into the M4 Neural Engine architecture. While official sources confirm hardware-level throughput improvements for int8 operations, independent benchmarks reveal complex trade-offs between GPU and Neural Engine execution paths, particularly for Large Language Model decoding.

Assignment angle: Focuses on the specific technical gains in inference speed and memory efficiency for 4-bit models introduced by the latest CoreML framework updates on M4 chips.

FIELD NOTE

Neural Engine Throughput Improvements on M4

Apple's Core ML Tools documentation explicitly notes that newer hardware, including the M4 chip, offers increased throughput for int8-int8 compute on the Neural Engine compared to previous generations. This hardware-level enhancement is critical for models that rely on integer arithmetic to maintain speed while reducing memory footprint. The documentation recommends using activation quantization primarily when the model is fully or mostly running on the Neural Engine, suggesting that the performance gains are contingent on keeping the computation on this specific accelerator.

This optimization aligns with the broader trend of moving heavy AI workloads to specialized silicon. By improving the efficiency of int8 operations, Apple enables more complex models to run within the thermal and power constraints of mobile and laptop devices. However, the documentation also implicitly warns that these gains are not universal across all execution paths, emphasizing the importance of framework-level optimization to leverage the hardware capabilities fully.

  • M4 chips provide increased throughput for int8-int8 compute on the Neural Engine.
  • Activation quantization is recommended only when models run mostly on the Neural Engine.
  • Performance gains are specific to newer hardware generations like A17 Pro and M4.

Core ML Overhead and Latency Trade-offs

Despite hardware improvements, independent analysis suggests that the Core ML framework introduces significant overhead for certain workloads. Benchmarks of the M4 Neural Engine indicate that Core ML adds 2-4x overhead for small operations, a gap that narrows only at high-throughput configurations where compute time dominates. For latency-sensitive tasks such as LLM token decoding, this 'Core ML tax' can be severe, potentially negating some of the hardware-level speedups.

Furthermore, the effective performance of the Neural Engine may not always match theoretical peak claims. One technical deep-dive notes that INT8 performance can sometimes equate to FP16 performance in real-world scenarios, challenging the '38 TOPS' marketing figure. This suggests that while the hardware is capable, the software stack's efficiency is the primary bottleneck for small-batch inference tasks common in interactive LLM applications.

  • Core ML adds 2-4x overhead for small operations on the Neural Engine.
  • Latency-sensitive workloads like LLM token decoding suffer from framework overhead.
  • Real-world INT8 performance may not consistently exceed FP16 performance.

FIELD NOTE

GPU vs. Neural Engine for LLM Inference

The choice between using the GPU and the Neural Engine for LLM inference remains a critical architectural decision. Recent benchmarks from the 'apple-silicon-llm-bench' project show that Qwen3-8B 4-bit models decode at 94 tokens per second on an M4 Max GPU, while MLX achieves 90 tokens per second under similar conditions. These figures highlight the GPU's continued dominance in raw throughput for large language models, even as the Neural Engine receives specific quantization optimizations.

The distinction is further complicated by the emergence of 'Core AI' as a successor to Core ML in future operating systems. This new runtime aims to streamline the export of PyTorch models into .aimodel bundles for execution on either the GPU or Neural Engine. However, current evidence suggests that for many LLM workloads, the GPU remains the more predictable and performant choice, particularly when avoiding the overhead associated with Neural Engine dispatch.

  • Qwen3-8B 4-bit decodes at 94 tok/s on M4 Max GPU.
  • MLX achieves 90 tok/s under the same protocol.
  • Core AI is emerging as the successor to Core ML for on-device ML.

Quantization Strategies and Memory Efficiency

Quantization remains the primary method for fitting large models into the unified memory architecture of Apple Silicon. Discussions around M4/M5 architecture emphasize the importance of leveraging Core ML and MLX to manage memory efficiently. Techniques such as W4A16 (4-bit weights, 16-bit activations) and INT4/INT8 quantization are standard, but their effectiveness depends heavily on the underlying hardware support. The M4's improved int8 throughput specifically benefits models that can tolerate integer activations without significant accuracy loss.

However, the complexity of managing these quantization schemes across different accelerators (GPU vs. ANE) requires careful tuning. The 'llms-on-apple-neural-engine' repository highlights various quantization formats and their impact on prefill, throughput, and thermals. This indicates that while 4-bit quantization is widely supported, the optimal configuration for speed and memory efficiency is highly dependent on the specific model architecture and the chosen execution backend.

  • W4A16 and INT4/INT8 quantization are key strategies for LLMs on Apple Silicon.
  • Memory efficiency is tied to unified memory architecture and quantization precision.
  • Optimal quantization depends on the specific model and execution backend.

Closing read

Conclusion

The latest updates to Apple's Core ML framework and M4 hardware demonstrate a clear intent to optimize on-device AI performance, particularly for integer-based computations. The increased throughput for int8-int8 operations on the Neural Engine represents a tangible hardware improvement that can benefit quantized models. However, the evidence suggests that these gains are not automatically realized across all workloads. The significant overhead introduced by Core ML for small operations and the continued strong performance of the GPU for LLM decoding indicate that the Neural Engine is not yet a universal solution for all on-device AI tasks.

Developers must navigate a complex landscape of frameworks, including Core ML, MLX, and the upcoming Core AI, to achieve optimal performance. While the hardware capabilities of the M4 are impressive, the software stack's efficiency remains the deciding factor for latency-sensitive applications like LLMs. The future of on-device AI on Macs will likely depend on reducing the abstraction overhead of these frameworks, allowing developers to more directly leverage the specialized compute units without the 'Core ML tax.'

Five takeaways

  • M4 chips offer increased int8-int8 compute throughput on the Neural Engine.
  • Core ML adds significant overhead for small operations, affecting LLM token decoding.
  • GPU currently outperforms Neural Engine for Qwen3-8B 4-bit decoding on M4 Max.
  • Activation quantization is most effective when models run primarily on the Neural Engine.
  • Core AI is set to replace Core ML as the primary on-device ML runtime.
